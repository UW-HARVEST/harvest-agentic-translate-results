## Feature combinations

`translation/Cargo.toml` declares **no `[features]` table**, therefore the
complete set of feature combinations is:

| # | combination | cargo invocation |
|---|-------------|------------------|
| 1 | default (empty) | `cargo test` |
| 2 | `--no-default-features` (identical to #1, no features exist) | `cargo test --no-default-features` |

Both are exercised by `run_all_configs.sh`.

In addition, because the *compiled profile* changes real behaviour for a Rust
translation (`overflow-checks`, `debug-assertions`, `panic=abort`), **three**
cdylib profiles are built, loaded and differentially tested — every test runs
against all three:

| profile | path | `opt-level` | `overflow-checks` | `debug-assertions` (Rust UB checks) | `panic` |
|---------|------|-------------|-------------------|-------------------------------------|---------|
| `dev`     | `target/so-dev/debug/libnext_double_lib.so`     | 0 | **on**  | off    | unwind |
| `release` | `target/so-rel/release/libnext_double_lib.so`   | 3 | off     | off    | abort  |
| `ubcheck` | `target/so-ubc/ubcheck/libnext_double_lib.so`   | 0 | **on**  | **on** | unwind |

Every one of the three exports exactly `next_double`, matching the C:

```
target/so-dev/debug     -> next_double
target/so-rel/release   -> next_double
target/so-ubc/ubcheck   -> next_double
target/release          -> next_double
C                       -> next_double
```

`translation/rust_syms.txt` is regenerated by
`tests/symbol_parity.rs::record_symbol_tables` on every run.
