# CONFIGS.md — configuration surface for VALID inputs (Phase A, gate for Phase B)

## How the axes were derived

`c_src` has no build-time options (`grep -c '#ifdef\|#if ' c_src/src/lib.c` → 0),
no global state, no init/teardown, and no allocation. Every function is a pure
value transform. So the configuration surface is exactly:

**Axis 1 — entry point.** All 22 exported symbols, *including* the lowest-level
ones (`c2V` … `c2MulmvT`), not just `spec_ray`. The call hierarchy from
`include/lib.h` downwards is
`spec_ray → c2CastRay → {c2RaytoCircle, c2RaytoAABB, c2RaytoCapsule} →
{c2AABBtoAABB, c2AABBtoPoint, c2CircleToPoint, c2Norm, c2MulmvT, c2CCW90,
c2Skew, c2Minv, c2Maxv, c2Absv, c2Mulvs, c2Div, c2Len, c2Dot, c2Add, c2Sub, c2V}`.

**Axis 2 — the one runtime "mode" selector in the public API:** `C2_TYPE typeB`
passed to `c2CastRay`. Three valid variants (`C2_TYPE_CIRCLE = 0`,
`C2_TYPE_AABB = 1`, `C2_TYPE_CAPSULE = 2`), each selecting a completely
different code path, each requiring a differently-shaped `B` payload
(`c2Circle` 12 B, `c2AABB` 16 B, `c2Capsule` 20 B).

**Axis 3 — value class of every `float` the code branches on.** The C branches
on sign (`< 0`, `> 0`), on equality with `0`, and on `<= 1.0f`, so the
distinguishable classes are: normal positive, normal negative, `+0.0`, `-0.0`,
subnormal, large-but-finite, overflow-to-`inf` magnitude, `±inf`, `NaN`, and
values that make two sides exactly equal (boundary ties).

**Axis 4 — geometric shape / branch selection.** Enumerated below per raycast
function by reading its `if`/`else` chain, since that is what the C actually
distinguishes:

* `c2RaytoCircle` — `disc < 0`; `t < 0`; `t > A.t`; hit.
* `c2RaytoAABB` — swept-AABB reject; separating-axis reject; `hit == 0`;
  and the **four-way tie-break chain** that picks the normal
  (`t0` wins → `(-1,0)`; `t1` → `(1,0)`; `t2` → `(0,-1)`; `else` → `(0,1)`),
  times the three sub-branches of `c2RayToPlane_OneDimensional`
  (`da < 0`, `da*db > 0`, `d == 0`, general) for each of the four planes.
* `c2RaytoCapsule` — nine distinct outcomes: (a) `yAp` inside `capsule_bb`;
  (b) `A.p` inside end-circle `a`; (c) inside end-circle `b`;
  (d) straddle & `|yAp.x| < r` & `yAp.y < 0` → delegate to circle `a`;
  (e) same but `yAp.y >= 0` → circle `b`; (f) `|yAp.x| >= r`, slab `t`, `y <= 0`
  → circle `a`; (g) `y >= yBb.y` → circle `b`; (h) slab side hit, normal is
  `M.x` when `c > 0` else `c2Skew(M.y)`; (i) fall through to `0`.
  Times capsule orientation (vertical, horizontal, diagonal, reversed `b`→`a`).

**Method for every row.** Both `.so`s are loaded with `libloading` and the
symbol is called through its `extern "C"` pointer. Inputs are generated by a
fixed-seed SplitMix64 PRNG (`tests/common/mod.rs`), **many** per row
(1 000–200 000 depending on cost), drawn from a distribution biased towards
that row's configuration and mixed with the special value classes from Axis 3.
Comparison is on **raw bits**: return `int` compared exactly, `f32`/`c2v`
compared via `to_bits()`, and the whole 12-byte `c2Raycast` out-parameter
compared as bytes including the pre-fill pattern (so "not written" is
distinguishable from "written with the same value").

A row is checked only after it passes across all of its randomized inputs.

## Test adequacy (why these rows are believed to be sufficient)

Passing rows only prove that *this* Rust matches *this* C. To check the rows are
actually sensitive rather than vacuous, 18 deliberate mutations were injected
into `src/lib.rs`, each rebuilt (`cargo build --release`) and run through the
full suite with `--no-fail-fast`:

| mutation | tests that caught it |
|----------|----------------------|
| `ter_abs` → `f32::abs` (differs only on `-0.0`) | 2 |
| `ter_min` → `f32::min` (differs on `NaN`, `-0.0`) | 5 |
| `c2Dot`'s `addss` destination flipped (NaN payload only) | 3 |
| `c2Div` reciprocal-multiply → true division (1 ULP) | 32 |
| `c2CastRay` UB arm → `return B` (the `-O2` behaviour) | 2 |
| `c2CircleToPoint` `<` → `<=` | 6 |
| `c2RaytoCircle` `t <= A.t` → `t < A.t` | 8 |
| `c2RayToPlane_OneDimensional` `d == 0` guard removed | 2 |
| `c2Skew` sign flipped | 15 |
| capsule side normal `c > 0` → `c >= 0` | 5 |
| capsule side normal else-arm → `M.y` | 13 |
| capsule `out->t = t*A.t` → `t` | 12 |
| capsule `y >= yBb.y` → `y > yBb.y` | 3 |
| `c2RaytoAABB` `t2` arm normal `(0,-1)` → `(0,1)` | 15 |
| `c2RaytoAABB` `hit_i` `<=` → `<` | 2 |
| `spec_ray` `ray.t` subtraction order swapped | 8 |
| `c2AABBtoPoint` `d2` `>` → `>=` | 4 |
| capsule side normal `c2Skew(M.y)` → `-M.x` | **0 — provably equivalent** |

17 of 18 were caught. The survivor is not a gap: `c2CCW90(v) = (v.y, -v.x)`, so
`-c2CCW90(v) = (-v.y, v.x) = c2Skew(v)`, and IEEE negation is an exact sign-bit
flip for every encoding including `NaN` and `±0`. The two expressions are
bit-identical on all inputs, which is what a surviving equivalent mutant looks
like.

Two mutations are worth singling out. The `ter_abs` and `c2Dot`-destination
mutations are invisible to every value except `-0.0` and NaN pairs
respectively, and each was still caught — which is the evidence that the
signed-zero rows (58) and the NaN-payload rows (3, 17) are doing real work
rather than passing by luck.

## Harness note

`cargo test` builds the integration-test binaries but **not** the `cdylib`,
because the tests `dlopen` the library instead of linking it. A bare
`cargo test` after editing `src/lib.rs` would therefore load a stale `.so` and
report a false pass. `tests/common/mod.rs` compares the two mtimes and aborts
with a `STALE LIBRARY` message if that happens; `verify_all.sh` always builds
before testing.
