# ERRORS.md — the error surface of libpng (C ground truth)

Every row is a distinct place where the C library rejects or complains about an
input.  The table is generated by `tools/gen_errors.py`; do not edit it by hand.

All three scans are restricted to code the reference build actually **compiles**:
the line lists come from the real C preprocessor (`cc -E -std=c99 -I
c_src/include`), so a diagnostic inside an `#if`/`#else` branch that
`c_src/include/pnglibconf.h` disables is excluded — it is dead code in
`libpng.so` and no input can reach it.  (That removes, for example, the
`"PNG_WRITE_BGR_SUPPORTED is not defined"` family in `pngwrite.c`.)

| part | what | rows |
|------|------|------|
| 1 | diagnostic rejections (`png_error`, `png_warning`, `png_chunk_*`, `png_app_*`, `png_benign_error`, `png_fixed_error`) | 368 |
| 2 | silent sentinel-return rejections (`return 0 / NULL / -1` behind a check) | 118 |
| 3 | silent void-return rejections (`return;` behind a check) | 218 |
| 4 | generic FFI-boundary rejections (NULL, out-of-range enum, bad length) | 6 |

**`assert()`**: libpng contains none.  `grep -n assert c_src/src/*.c` finds
exactly three hits and all three are comments (`png.c:116`, `pngrtran.c:2452`,
`pngrtran.c:2467`).  The only abort path is `PNG_ABORT()` (`= abort()`,
`pngpriv.h:580`) at `pngerror.c:690`, reached from `png_longjmp` when the
application installed neither a `jmp_buf` nor a `png_longjmp_fn` — row **G-1**
in part 4.

## How a row is checked off

`tests/errors.rs` (and every other test file) drives BOTH shared libraries
through the same input and compares the complete ordered trace of
`(warning|error, message)` events plus the return values and output bytes.
Only *after* a comparison has succeeded is the diagnostic recorded, so a
recorded message is by construction one that both libraries produced
identically.  `tools/error_coverage.py` then diffs the union of everything the
whole suite recorded (`target/observed/*.txt`) against part 1 and writes
`ERROR_COVERAGE.md`; `--stamp` copies the result into the `seen` column below.
So the check-marks are machine-derived, never hand-asserted.

The `seen` column has three states: `[x]` the suite observed this exact
message from both libraries; `[-]` the message is assembled at run time (a
variable, or `png_formatted_warning` parameters) so there is no literal to
match on -- the site is still exercised, it just cannot be checked off by
text; `[ ]` not reached, see the list at the end of `ERROR_COVERAGE.md` for
why (all of them are internal-consistency guards, need a >2 GiB object, or
are shadowed by an identical earlier test in the same function).

Parts 2 and 3 are silent rejections: they have no message to observe, and they
are covered exhaustively by `tests/sweep.rs::null_arguments`, which calls all
381 exported entry points with NULL/0 in every position and compares the return
value, and by `tests/sweep.rs::hostile_scalars_*` / `enum_boundaries` /
`length_boundaries`, which do the same with a live `png_ptr` and out-of-range
scalars.

## Part 4 — generic FFI-boundary rejections

These are not tied to one source line; they are the boundaries every C API has.
All six are covered exhaustively (over **all 381 exported entry points**) by
`tests/sweep.rs`, which runs each call in a forked child so that a call which
is fatal to the C library is a *compared observation* rather than the end of the
test run.

| # | trigger | expected C result | test |
|---|---------|-------------------|------|
| G-1 | `png_error`/`png_longjmp` with neither a `jmp_buf` nor a `longjmp_fn` installed | `PNG_ABORT()` -> `abort()` -> SIGABRT | `errors::png_abort_row_A1` |
| G-2 | NULL in every pointer argument of every entry point | mostly an early `return`; a NULL deref where the C dereferences before its own guard (e.g. `png_write_chunk_start`) | `sweep::null_arguments` |
| G-3 | out-of-range enum value (no valid variant) in every scalar argument | per-function: clamp, `png_app_error`, `png_warning`, or silently ignored | `sweep::hostile_scalars_read` / `_write`, `sweep::enum_boundaries` |
| G-4 | one step past each documented enum range (`PNG_*_LAST`, `PNG_OPTION_NEXT`, …) | as G-3 | `sweep::enum_boundaries` |
| G-5 | zero length / size where a positive one is expected | early return or `png_error` | `sweep::length_boundaries`, `errors::setter_validation` |
| G-6 | oversized length (`0x7fffffff`, `0x80000000`, `0xffffffff`, `SIZE_MAX`) | allocation failure -> `png_error`/`png_warning`, or a range check | `sweep::length_boundaries`, `errors::user_limits_rejections` |
