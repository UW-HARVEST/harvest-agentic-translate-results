# ERRORS.md — error / rejection surface of the C implementation

Derived **mechanically** from `c_src/src/*.c` (`tmp/gen_errors.py`): every call to an
error/warning/report macro, every sentinel `return 0 / NULL / -1` in an *exported*
function, and every `assert`.  One row per distinct rejection site.

Semantics of the "expected C result" column (see `pngerror.c`, `pnglibconf.h` —
this build has `PNG_BENIGN_ERRORS_SUPPORTED` + `PNG_BENIGN_READ_ERRORS_SUPPORTED`
but **not** `PNG_BENIGN_WRITE_ERRORS_SUPPORTED`, and `PNG_ERROR_NUMBERS` is off):

* `png_error` / `png_chunk_error` / `png_fixed_error` — call `error_fn` with the exact
  message, then `longjmp` (harness returns non-zero `rc`).
* `png_app_error` — fatal unless `PNG_FLAG_APP_ERRORS_WARN` (set by
  `png_set_benign_errors(1)`), else a warning.
* `png_benign_error` / `png_chunk_benign_error` — on a **read** struct: warning when
  `PNG_FLAG_BENIGN_ERRORS_WARN` is set, otherwise fatal; on a **write** struct always fatal.
* `png_warning` / `png_app_warning` / `png_chunk_warning` — `warning_fn` with the exact
  message, execution continues.
* `png_chunk_report(..., PNG_CHUNK_ERROR|WARNING|WRITE_ERROR)` — dispatches to the above.
* `png_image_error` — simplified API: stores the message in `image->message`, returns 0.
* `png_zstream_error` — records a zlib message consumed by a later error/warning.

Every row is exercised by the Phase C differential tests: both libraries are driven
into the condition and the *complete* message/return trace must be byte identical.
Coverage is verified mechanically by `tests/error_coverage.rs`, which records every
message string emitted by the C library and requires the Rust library to emit the
identical sequence (see `ERROR_COVERAGE.md`, regenerated by `tmp/coverage.py`).
